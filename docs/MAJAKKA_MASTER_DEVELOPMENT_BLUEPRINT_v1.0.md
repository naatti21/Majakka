## 1. Product and pillars
Restore the Light. Reconnect the World. A living GPS-based world with collection, exploration and cooperative spatial strategy. Ingress is an interaction reference for real POI networks; Pokémon GO and Jurassic World Alive are references for the excitement and skill of encounters, not assets or mechanics to copy wholesale. No compulsory daily maintenance or hostile PvP destroying weeks of work. One shared world is the eventual goal; until server authority is proven, explicitly label a local pilot. User decides final balancing and release.
Core loop: real location and signal -> meaningful choice (investigate a Node, encounter a Kaiku, or improve a route) -> earn/use Lumen or knowledge -> choose progression/companion -> restore Nodes and build links -> fields alter signals and events -> discover more Kaiku and research. Each branch should be useful by itself and feed the others. Do not force a player to complete one loop before every other action. Movement improves opportunity, not mandatory attendance.
Three scales: minute encounter, 5–15 min meaningful nearby expedition, weeks/months persistent network, collection and specialization. The player should be able to explain what just changed and what they can do next.

## 2. World and Atlas: a complete geographic model, not a complete global dataset on day one
Basemap: MapLibre GL JS, existing Dark readable style and free camera, online vector tiles. Three.js custom layer after basemap, preserve clearDepth fix; use map engine for roads/labels, never hand-model cities or switch engines to hide a bug. World map can pan and zoom globally. Gameplay coverage is a separate data layer; show region loading, empty or unavailable honestly.
WorldAtlas pipeline: Overture Places / OSM / relevant municipal datasets -> normalize provider IDs, name, type, provenance, date, coords and license -> filter exclusions -> independent public pedestrian access/path validation -> deduplicate and deterministic spacing/category distribution -> persistent worldNodeId and source aliases -> versioned published region chunks -> client cache and fetch by viewport tiles. Do batch imports, not mass Overpass requests from clients. Real pilot starts Tampere AND Nokia/less dense area; then rural and larger regions. Existing sourced pilot-sites.js may seed a smoke test, but eight old source records are not an automatically generated catalogue. Verify current provenance and classifications. Existing atlas-autogen.js is a candidate chooser, not a verified GIS importer. Old atlas-core.js 4 categories do not equal 6 Node types. Gate2 catalogue policy is a draft; preserve its identity and safety checks and document schema adapter.
Never interpret map viewport/zoom as discovery or movement. Same catalogue version -> same IDs and coordinates across players and overlapping viewports. Source edits use alias/migration/removal, not respawn; link to stable ID. Cache chunks (version/ETag); fetch on settled viewport with bounded concurrency, cancel stale requests, cap visible 3D models; use far LOD/cluster and preserve world state. Global links need geodesic geometry and antimeridian handling; local 3D scene origin rebasing/tiles prevent Mercator precision drift. Do not pretend whole world is loaded at once.
Access distinction: valid POI with verified approach can be a walkup candidate, but no claim of guaranteed safety. Unverified approach -> remote-only as in AutoGen; do not send its exact game-anchor coordinate to client or create a map pin that invites approach. Source catalog may retain coordinates for private derivation. Publicly display only eligible approved geographic anchors; remote-only records show in area research, not visit instructions. For limited internal GIS QA, restricted previews must not become public targets. Exclude private residences, schools, restricted areas, waterways, road/rail hazards, unsafe access and ambiguous geometry; require real pedestrian evidence. Add flag/report and remove path; no unsupported automatic access guarantee. OpenStreetMap attribution and license/combined DB review before production. No camera-generated fictional POIs. Published canonical regional phenomena may support rural play but explicitly fictional, not navigable physical anchors.
GPS: explicit permission, foreground watch, accuracy/freshness/speed checks, stop on hidden/permission revoked; show uncertainty. Never store exact route or publish positions; preserve private sanctuaries concept (home/work/three chosen places) separately, no disclosure or public links. GPS/camera/action centre are distinct. 150 m nearby interaction is user's trial preference, NOT same as 70 m movement-Lumen rule nor Gate1 distance-effectiveness curve. Accurate fix and conservative reach (including accuracy margin) required; fail gracefully if location unavailable. Remote investigation/collection/network planning stays useful, no GPS spoof via panning. Server validates actions before shared play; do not claim tamper-proof GPS.

## 3. Nodes, links, fields and resource economy
Existing six Node functions (Node Atlas): Prism / art / frequency & light; Archive / history / memory fragments; Grove / nature / calm interference; Relay / route / transmit and alternative paths; Observer / viewpoint / distant weak signals; Commons / library-culture / collective memory. Separate type from material grade. Proposed prototype material pairings from node-family-v01: Porcelain, Stone, Moss, Copper, Pearl/Mineral, Timber respectively. Not final canon. Each has its own recognizable lighthouse body/crown/material, not recolored identical tower. Dormant vs awakened vs affected distinct and readable at all zooms.
Tap actual map Node -> real name/provenance, type, status, reach, meaningful action and consequences. Node charge/research uses existing candidate reducers, not hard-coded free three links. Link explicitly select two awakened Nodes, preview cost, distance, effect, then commit through graph rules. A triangle only when 3 valid committed edges. Shared fields and personal focus are separate: Beacon / Shelter / Lens (candidate rules) allow distinct effects; choose use, not overwrite others' field. No area-size passive Lumen yield; never auto-link because Nodes are close. Links persist, no ownership war.
Lumen: movement sampling with anti-jitter and daily budget; local virtual collectible grains where appropriate, stationary channel/knowledge route that avoids compulsory attendance. Reuse walk-energy.js and candidate wallet/node/graph logic via adapters; reconcile old local v0.11 first-chord auto-link against explicit graph rules, don't reintroduce it. Gate1 v1.2 candidate starting wallet 8, max 18, 2 L awakening/contribution, 20h channel and other numbers are UNAPPROVED candidate parameters, not final. Known risk: first session can get stuck before first complete field; model resource paths and offer a meaningful research route before acceptance. Balance table must be external, versioned and tested. No fake tap-generated energy or unbounded farming. Use separate XP (experience), Lumen (energy), research records and Kaiku identity; no unnecessary new currencies.

## 4. Collectable Kaiku ecology and encounter: NEW proposal for acceptance/playtesting
Old Echo terms used for both mystery task and creature: separate ResearchEcho (task), KaikuSpecies/Form/Instance, KaikuEncounter (opportunity). Preserve Flintail's approved identity Trailborn/Aera, Agile/Tracker/Field Sense, original visual references. No redesign or fake completed asset. Creature occurrences are fictional, with habitat affinity and region state; not real POIs. Build stable versioned spawn IDs and validity windows in a region catalog based on habitat, season/time if used, Node resonance and event context. Random selection seeded server-side eventually; never reroll by zoom/reload. World-wide ecology avoids urban-only rewards: safe public approach or remote encounter delivery; no inaccessible pins. Reserve meaningful common species even without awakened network; network unlocks different signals, not mandatory capture. A player may opt out of tracking, still use remote discoveries. No exact route history.
Encounter proposal: RESONANCE BOND, a short 15–30 s skill encounter in Kaiku's own environment. Tap encounter from map when within validated 150 m (or designated remote route); freeze gameplay scene safely while standing still. A moving Kaiku emits a recognizable 2–4 phase pulse. Read signal, track moving resonance window using drag/hold or accessible tap alternative, then release at alignment. Final choice: approach calmly or stabilize/trace if species or interference changes pattern. Skill accuracy, timing and chosen companion/talent determine harmony progress; success creates one unique KaikuInstance, not random pay-to-win loot. Good attempt yields meaningful clue/knowledge if not bonded; retry same encounter without reroll, capped reward and safe expiry/pause. No camera/AR or projectile required, no walking while interacting, no flashing or compulsory fine motor precision. Optional audio/haptic cues, high contrast/reduced motion/tap alternatives, adjustable practice; no forced audio or color-only cue. No payment or consumable required for first encounter. Difficulty via different behavior, moving windows, pattern lengths and environmental interference, not tighter timers alone. Test whether it is actually fun and repeatable after 20–50 encounters, not just technically playable.
Example behaviors (proposals, not canon): Flintail moves in quick bursts with short readable pauses; Grove-affine species has slow breathing pulses; rare disturbed Kaiku reveals false signal vs real one. Start Flintail only; additional species authored after benchmark. Tracking talent previews trajectory/echo, Bonding widens calm alignment opportunity, Weaving uses field information, Veilcraft distinguishes interference. Kaiku Echo Sense may combine with player Deep Tracking for Phantom Trail (old hybrid example, exact effect OPEN). Show why success/failure happened. Prevent single mandatory build: each core encounter solvable without talents.
Encounter state machine: offered -> engaged -> resolved(success/partial/fail) or cancelled/expired; idempotent reward, one collected instance per valid success, no duplicate claim on reload or concurrent request, no client-forged seed/result in shared mode; accessibility mode equivalent progression. Start with pure deterministic input reducer, store minimal attempt state and receipts, then integrate visual encounter overlay. Use synthetic QA input only in tests, clearly labelled; actual gameplay must have a source-backed nearby/remote encounter, not a debug list.
Collection: high-quality static grid, detail opens species-specific environment and 4–6 s seamless loop; one optional interactive 3D Inspect. Lightweight animated map creatures, LOD 2.5D/3D; primary companion can be true 3D. Preserve Species -> Form -> Instance -> Presentation. XP/Level distinct from Evolution and talents; duplicate evolution example ~10 excess -> 1–2 evolution levels is NOT locked. No direct trading. Never accidentally consume active/guardian/favorite specimen; explicit confirmation and immutable receipt. Do not create placeholders with final Flintail branding unless identity reference exists; mark temporary assets clearly.

## 5. Player and Kaiku talents: meaningful gameplay
Existing accepted design dimensions: classless Player Talent Web 24 nodes/14 points, four branches Tracking, Bonding, Weaving, Veilcraft. Kaiku tree 12 nodes/7 points per species, no permanent class lock; undo/reset possible conditionally, cost/cooldown undecided. 1 Primary + up to 2 Support is proposed representation of user's 1–3 active Kaiku. Other individuals can be Guardians at Nodes; no passive mandatory maintenance, stacking caps/retrieval TBD.
Proposed effect roles: Tracking signal resolution/forecast and discovery; Bonding encounter affordances and companion synergy; Weaving alternate link plans/field use; Veilcraft distinguish interference and alternate solutions. Flintail specializes in tracking and field sense, but other viable routes exist. Guardian contribution is limited and type-specific, e.g. Grove steadies affected signal, Observer reveals clue. Do not grant limitless global Lumen or passive stacking.
Data-driven talent graph: id, scope (player/species), prerequisites, point cost, effect IDs, unlock conditions, version and localization. Separate point ledger, allocated selections and effective gameplay modifiers. Validate no cycles, max budgets, reachable nodes, reversible choices, hybrid prerequisites, no same individual active and guardian; test builds and reset. First vertical slice only two meaningful tentative talents (one player, one Flintail) with measurable encounter effect; full 24/12 tree proposal + balance approval before implementing all abilities. No fake stat labels with no actual effect.

## 6. Opposing force — Interference (existing rule engine + proposed story/game effects)
Existing Gate1 rule candidate: Calm -> Signal -> Interference -> Recovery -> Calm. Candidate 24h warning, max 72h active, 48h recovery, individual -20 pp / total -40 pp. Not locked final durations. Existing four choices: Stabilize (cost and recovery), Investigate (knowledge without forced cost), Reroute (temporary own route), Ignore (safe and valid). Permanent Nodes, links, fields, research, collection never erased by absence. No debt, no mandatory dailies or PvP destruction.
Design proposal: The Veil (working narrative label, NOT locked) is dissonance in the world; not a new faction. Disturbance visible as broken light rhythm, uneven airborne mist or shadow-tinted pulse; never hide roads or safety information. Types: (A) Signal distortion -> ambiguous encounter cues, tracking/veilstudy reveals true pattern; (B) Strand turbulence -> temporarily lower effectiveness, alternative relay route or Grove guardian helps; (C) Memory fracture -> Archive research case, multiple evidence-driven solutions; (D) Habitat shift -> temporarily different Kaiku behavior/opportunities, no forced rare-chase. These are proposals on top of existing reducer, not a new competing rule engine. Each event has known duration, bounded effect, inspectable cause and remedy. Ignore is legitimate; after 21 days absence there is no permanent damage. No PvP, global alarm spam, subscription boosts or artificial time pressure. Local/remote accessible solution. First playable event = one existing reversible Interference type with visible consequence and one meaningful research or reroute action; use The Missing Beat research branch rather than inventing unrelated case. Later author 6 distinct expedition cases and 12 different decisions as older proposal targets, test variety rather than rote repetition.

## 8. Architecture, shared-world trust and state
Preferred PWA/MapLibre + Three.js existing stack. Client map reads WorldCatalog and WorldGraph snapshots; authoritative rules are DOM-free and tested. Architecture: data import -> catalog version -> world read service; player GPS/action centre -> action intent -> validated reducers -> receipts/snapshot -> UI and render. State is not computed from visuals. Use worldNodeId; stable linkId/fieldId from rules branch; KaikuSpecies/Form/Instance/Encounter IDs; player/account, wallet ledger, talent allocations, guardian assignments, event IDs, revisions. Render bindings derive from state; no hard-coded 3 points/triangle/stage, no duplicate rule implementations. For local pilot adapters persist versioned state separate from old demo, no silent destructive migration; atomic action and state update locally with storage error handling. Read previous state safely. Separate synthetic test and live sources.
Public multiplayer later: inspect existing Cloudflare Worker/D1 backend and decide reuse vs replacement via documented threat and cost assessment. Existing worker disabled, no live authority; don't enable anonymous writes. Server validates coordinates/catalog version/action centre, rate/accuracy/speed plausibility, session auth, permissions, idempotency (actor, operationId, payload hash), expectedRevision and atomic wallet+graph+encounter transaction. Reject replays/different payload, negative wallet, concurrent duplicate Kaiku, invalid talent budget, false GPS claims; logs redact private locations, retention/deletion and reporting. No secret in client, no personal location trails; use delayed aggregate privacy thresholds, not delay alone. Sync on foreground and recover conflicts; shared world online-authoritative, cached client view read-only if service unavailable; never present unsynced local truth as global. Offline encounters only if separately designed and reconciled. No paid services or premature scaling before pilot data.
Performance: mobile first (360–430 px), camera gestures, accessible semantic UI, 44 px targets; monitor actual FPS/frame time, GPU resource counts, battery/thermal and loading on weak and target Android. Target 30+ sustained FPS on agreed test device as hypothesis, no guarantee. CI viewport/WebGL tests vs physical device and independent QA separate. Use Playwright on Ubuntu 24.04 or verified current support, node --test tests/*.test.mjs, node --check backend/worker.mjs. Art QA inspect actual screenshots, not only file existence. No main/deploy before explicit approval and risk-based GO; docs may be stored without changing game code.
