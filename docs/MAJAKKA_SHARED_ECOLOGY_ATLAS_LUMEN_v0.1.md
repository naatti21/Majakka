# MAJAKKA — Shared Ecology, Atlas Automation & Lumen v0.1
Date 2026-11-25. Owner direction + engineering proposals. This delta supersedes incompatible earlier per-player spawn, movement-only Lumen and manual-world generation proposals. It does not approve exact balance or change current S1 code.

## 1. One world, all players
OWNER DIRECTION: Nodes and Kaiku occurrences are the same for everyone. Same published world version, region and server time -> identical stable Node IDs, location/type, public awakening state, committed links and fields, Kaiku occurrence ID/species/form/location/validity and interference. No per-player spawn seed, camera-generated POIs, device-clock reroll, refresh reroll or private substitutes presented as shared occurrences. Client LOD, tracking talent hints, visibility fog, accessibility and GPS range may affect what a player can discover/interact with, never the canonical underlying world. Companion/Guardian and collected KaikuInstance, talents, personal notes and wallet belong to player. A Companion is not a shared wild spawn. ResearchEcho remains separate from Kaiku.
PROPOSAL: individual capture/Resonance Bond attempt and receipt for each actor+occurrence; one player's success does not consume encounter for everyone. Same species/form/location/window, same underlying encounter difficulty/pattern seed; player talents modify affordance not spawn. Multiple players can meet and collect the same encounter once each. No personal rare spawn from talent. Shared occurrence remains until server-defined expiry; engagement deadline/grace policy TBD. Never lure player onto unsafe ground. Remote encounter path may access same shared occurrence if its policy permits, no fake GPS. Collection instances have unique IDs. Owner acceptance of nonexclusive capture still pending.
Implement versioned immutable regional catalog + server-authoritative snapshots and event journal. Common deterministic generator seeds derive from world version + region ID + UTC epoch + published event revision, not actor. Central authority materializes and signs/serves occurrence IDs and canonical state, schedules updates in batches; clients read/cache, do not decide new occurrences. Cross-boundary spawn assignment deterministic, one canonical home region, neighboring tile lookup and dedupe. Shared-world test: two accounts/devices and overlapping viewports -> same IDs/coords/species/validity/state; one Node action observed on other; same occurrence collectable once per actor under proposal; retries, concurrency, stale/offline time and version transition tested. No published player routes, precise live positions or identity-linked telemetry. Existing S1 local pilot is NOT this server.

## 2. Atlas Factory — automatic real POI selection
OWNER DIRECTION: automate Node formation at scale, include statues, churches and other meaningful public landmarks; sufficient rural content including distinctive rural types. No fake physical POIs. Existing AutoGen remains seed of pure deterministic policy but current tiny S1 data is insufficient. Old S1 contains one dataset-reviewed walking anchor and six remote records. Expand real source coverage before claiming network playability.
Source pipeline: periodically ingest licensed Overture Places, OSM POIs + pedestrian/land-use geometry, municipality/cultural heritage datasets, applicable nature/recreation data. Preserve provider identifiers, source license and revision. Normalize candidate classes, validate named/meaningful, reconcile duplicate source features, calculate legal/public approach with actual public walking network and exclusions, evaluate map density and coverage, publish canonical versioned chunks. Separate source POI geometry, public approach and client presentation coordinate. Church building footprint or statue centroid not automatic access proof. Public area or safe public approach required; do not direct players into worship, services, cemetery, private grounds, road, rails, schools, sensitive habitat, protected/closed areas. Respect signage, opening constraints and reports/withdrawals. No unsafe/unknown remote-only exact client anchor. Human review reserved for uncertain/risky cases and sample audits, not every ordinary POI; release safety gates still apply. No per-client bulk Overpass.
Candidate types mapping proposals (retain six existing gameplay classes; no seventh class automatically):
- public statues, sculptures, murals, public artwork -> Prism; historical memorial if history primary -> Archive.
- churches and publicly accessible historical buildings, ruins, monuments -> Archive by default when evidence supports; Commons only if appropriate communal function. Exclude sensitive burial grounds or restricted access.
- libraries, public culture/community facilities -> Commons; parks, public nature trail destinations -> Grove.
- marked public trailheads, wayfinding signs, public route junctions -> Relay; public viewpoints and observation towers -> Observer.
Rural variety: real public nature trailheads, hiking shelters where lawful, nature information boards, maintained viewpoints, geological landmarks/erratics, publicly accessible heritage mills and ruins, village monuments, public bridges only safe pedestrian approach (not road/rail), birdwatching towers outside restrictions. Map to existing classes with rural visual variants and environment-specific research/Kaiku affinities. Do not turn a random forest coordinate, private barn or every tree into a Node. Author explicitly fictional regional research if no eligible POIs. Don't make rural-exclusive species permanently inaccessible to urban players; alternative encounters through expeditions/region events may be designed later.
Density: adapt spacing and maximum active visible landmarks by settlement/road accessibility rather than one universal minimum. Urban and suburban demand different distribution, sparse regions may permit larger spacing and longer discovery horizon; no fixed invented counts. Score category significance, source corroboration, accessibility, geographic diversity and marginal coverage gain; choose deterministic set with stable IDs and seeded tie breakers. Avoid duplicate or visually crowded sites, do not lower safety threshold for countryside. Track eligible nodes per km², reachable nodes from public network, typical distance to nearest node, percent players with multiple nodes in a walkable area, category diversity, rural/urban comparison, false-positive/exclusion sampling, source freshness and cost. Density goals for Tampere/Nokia/Ruovesi before S2: enough verified real anchors for meaningful selection/triangle where geography permits, not guaranteed triangle everywhere; no invented fill. Pilot in city, suburb, rural. Actual import/provenance and review counts required.

## 3. Parviäly / swarm intelligence — proposal
Use swarm idea for offline world curation and bounded ecological simulation, not an LLM per POI/spawn or independent agents publishing into live world. First implementation is simple deterministic multi-signal scoring. If it fails coverage/diversity tests compare an optimization algorithm (e.g. greedy coverage vs ant-colony-style exploration/consensus) with cost, reproducibility, quality and constraints. Candidate generator, map-access checker, dedup checker, density optimizer, ecology planner, QA audit may be separate deterministic workers or optional agents. They propose and cross-check evidence; hard safety exclusions and canonical publisher cannot be overridden by a vote. Human reviewer handles ambiguity. All decisions auditable with source revision/reason, versioned weights, reproducible seed. No AI hallucinated landmarks.
Player crowd feedback later: voluntary site reports / suggestions, independent confirmations of public approach/existence, quality weighting and abuse/rate limits; no published GPS trails, no rewards for raw submissions, no popularity-based override of exclusion; disagreement queues review. Aggregate signals for habitat/coverage only privacy-protected. Don't use live player positions or personal movement routes as spawn seed. Avoid rich-city feedback bias. No autonomous external agents assumed available.
Kaiku ecology proposal: region/terrain/habitat affinity (park, water-adjacent safe path, woodland, cultural history, urban, rural), resonant Node type/field, time window/season, reversible Interference. Shared scheduler produces stable spawn groups using local habitat rules, bounded carrying capacity and nearby population/avoidance; a lightweight offline/periodic swarm-like model may make patterns emerge rather than hand-place every creature. Canonical server writes results and fixed validity interval; optional animations are presentation-only. Seeded deterministic motion/patrol inside safe interaction zone and timestamp, no phone-side physics deciding actual spawn location. Dense and sparse habitat tests, no inaccessible spawn, no forced rush, no global CPU simulation each frame. Start one Flintail encounter and compare actual enjoyment before complexity.

## 4. Lumen auto-collection, separate range
OWNER DIRECTION: automatically collect nearby Lumen, small separate range; no tapping every grain. Channel cooldown shorter idea '10cd' with no time unit given, tentative (DO NOT convert to minutes/hours as fact). Ask/confirm or compare named hypotheses before implementing new cooldown. Current candidate +4 / 20h remains only provisional reference.
PROPOSAL: shared ephemeral Lumen grain IDs and canonical eligible safe public-path location/window (never directional invitation to unsafe ground). Player's foreground fresh GPS reaches grain within separate collection range with accuracy check -> automatic one claim/actor/grain/window, wallet and claim receipt atomically; visual grains flow to avatar, subtle optional haptic/sound, no tap. Other players may collect the same grain individually under proposal, shared occurrence unchanged. Proposed small range 15–30 m as trial, test GPS uncertainty and practical walking; 150 m Node/Kaiku interaction remains separate, 70 m movement-Lumen current S1 separate. No collection by panning camera, duplicate GPS samples, repeated refresh or speed cheating. Show collected and wallet full; no lost grain claim on full wallet. Use spatial query around GPS, not camera. No exact route persistence. If precision insufficient, wait or use accessible channel/remote route; avoid encouraging unsafe movement. Stop on background until separate native permission design; no background collection promised. 
Economy: avoid triple payment for walking, grains and channel. Compare (A) grain collection replacing distance-based payment, (B) shared bounded budget, where grains and distance bonuses coexist only if balance tests show need. Prefer A for clear causality, keep movement-only S1 as legacy baseline until owner approves. Daily cap, amount per grain, density, regeneration and cooldown all tunable candidate config; check first-session field cost, urban/rural and home play parity. Channel is an optional stationary activity, no compulsory daily attendance. Simulate 10-min, 10-hour (only illustrative interpretations) and current 20h cooldown; no silent change. Rate and cooldown server clock, atomic per-player wallet, idempotent operations, no passive infinite farming. No final values accepted.
